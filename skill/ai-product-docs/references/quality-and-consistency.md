# 质量与一致性检查

## 事实与证据

- 外部可变信息是否带来源与日期？
- 数据、用户原话和研究结论是否能追溯到 `SRC-*`？
- 未验证内容是否明确标为假设或 TBD？
- 是否存在互相冲突的数字、日期、版本或术语？

## 目标与范围

- 立项目标、产品目标、Agent目标、评测阈值和大盘 KPI 是否同向？
- 每个 P0 功能是否关联用户用例和目标指标？
- 非目标、范围外与延期项是否在下游文档中被误写为本期交付？

## 追踪链

至少检查：

`SEG/INS → UC → F/REQ → EVT/TC → EVAL/MET → RUN → DEC/ACT`

- 每个 P0 `REQ-*` 至少有一个正向和一个异常 `TC-*`。
- 每个关键行为指标至少有一个 `EVT-*` 数据来源。
- 每个核心 AI 能力至少有评测样本与指标。
- 每个高风险失败模式至少有降级或人工介入措施。

## AI 专项

- 模型名称是否带具体版本或访问日期？
- 提示词、知识库、工具和参数版本是否可复现？
- 是否分开报告质量、时延、成本、稳定性与安全？
- LLM-as-a-Judge 是否有评分量表、校准样本和人工抽检？
- 评测集是否检查污染、重复、切分泄漏和敏感数据？
- 非确定性测试是否规定重复次数和通过规则？

## 表格可用性

- 一行是否只表达一个稳定对象？
- ID 是否唯一、列名是否稳定、枚举是否定义？
- 公式、单位、时区、统计粒度、过滤规则是否完整？
- 空值是否用 TBD 并说明需要什么输入，而不是含糊写“无”？

## 交付摘要

完成生成或审计后，给出：

1. 已生成/更新的文档及版本。
2. 已确认的关键决策。
3. 最高优先级的风险与待确认项。
4. 因变更而需要同步更新的其他文档。
5. 建议的下一步，不代替用户做未授权的业务决策。
